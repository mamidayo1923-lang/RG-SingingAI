# P3.1 Dataset Pipeline

## Annotation JSON

Create one UTF-8 JSON file per WAV:

```json
{
  "phonemes": [
    {"label": "k", "start": 0.00, "end": 0.08},
    {"label": "a", "start": 0.08, "end": 0.42}
  ],
  "notes": [
    {"start": 0.00, "end": 0.42, "pitch": 60, "velocity": 90}
  ]
}
```

Times are seconds relative to the start of the WAV. Phoneme boundaries must be manually reviewed or generated by a separate aligner and then reviewed. P3.1 does not claim to perform acoustic forced alignment. The baseline builder rejects overlapping intervals and out-of-range timestamps.

## Build one training item

```powershell
python -m tools.build_training_dataset --wav .\RG_SingingAI_Dataset\audio\take.wav --annotations .\annotations\take.json --out .\training_npz\take.npz --vocab-json .\training_npz\phoneme_vocab.json
```

Output includes `log_mel[T,80]`, `phoneme_ids[T]`, `midi_pitch[T]`, `velocity[T]`, frame timestamps, vocabulary JSON, and feature configuration. ID 0 is reserved for unlabeled/padding frames. The `--vocab-json` file is shared and updated as new labels appear; use the exact same path for every take. IDs are stable and 0 is reserved for unlabeled/padding frames. Ensure all required phoneme labels have been registered before starting training; if the vocabulary grows later, retrain with the updated `--vocab-size`.

## Train

```powershell
python -m recording_tool.singing.train --data .\training_npz --out .\models\singing_melnet.pt --vocab-size 16 --epochs 30 --validation-ratio 0.2
```

**Important:** the trainer's internal random validation split is file-level only. For credible evaluation, create song/phrase-group-safe train/validation/test manifests with `tools/make_splits.py` and place only the training split in `--data`; use a separate run for evaluation. With the current small baseline, the reported loss is mel-prediction MSE, not a perceptual or singing-quality metric.

## Known limitations

- This is a dataset pipeline prototype, not a production singing synthesis system.
- `SingingMelNet` has no explicit duration model or production neural vocoder. Griffin-Lim output is expected to sound rough.
- Vocabulary mapping is shared when the same `--vocab-json` path is used for every take; different vocabulary files must not be mixed in one training set.
- The renderer's sample-rate/mel-filter inverse conventions still need a matching implementation before its audio output can be considered calibrated.
