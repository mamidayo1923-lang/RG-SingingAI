- 文書バージョン：3.0.0
- 文書種別：技術調査・公開研究の検証・システム設計資料
- 対象：可不（KAFU / CeVIO AI）に関する公開技術情報、および RG Singing AI の設計
- 更新方針：確認済みの事実、技術的な一般論、仮説、未確認事項を明確に分離する
- 注意：本資料は可不の非公開モデルの内部構造を断定するものではない

## 0. 本報告書の目的と検証方針

本報告書は、歌声合成ソフト「音楽的同位体 可不（KAFU）」について、公開情報と関連する学術研究を整理し、歌声合成システムの構成を技術的に考察するものである。

さらに、調査結果を RG Singing AI のデータ収録、特徴量抽出、学習、推論、音声生成の設計に応用するため、実装可能な要件と研究段階の仮説を区別する。

### 0.1 情報の分類

本報告書では、各記述を次の4種類に分類する。

| 分類 | 意味 |
|---|---|
| 公開情報で確認 | 公開された公式情報、論文、技術資料から確認できる |
| 技術的に妥当 | 一般的な音声・機械学習技術として成立するが、可不への採用は未確認 |
| 仮説 | 公開情報や動作特性をもとに推定したが、直接的な証拠がない |
| 未確認 | 判断に必要な仕様、学習条件、実装情報が公開情報から確認できない |

公開研究であることと、特定の商用製品に採用されていることは同義ではない。

したがって、関連研究で CNN や PeriodNet が発表されているという事実だけを根拠として、可不の内部モデルがそれらで構成されていると断定しない。

## 1. 開発主体とシステム構成

可不は、花譜をモチーフとした音楽的同位体シリーズの歌声合成ソフトウェアであり、CeVIO AI のソング機能を利用する製品である。

製品に関する公式情報では、可不の提供元として THINKR / KAMITSUBAKI STUDIO 関連の表記が確認できる。

歌声合成製品を分析する際は、少なくとも次の役割を分離して考える必要がある。

| 機能領域 | 役割 | 内部実装の公開状況 |
|---|---|---|
| 歌唱エディタ | 音符、歌詞、テンポ、パラメータの編集 | 操作仕様の一部は公開 |
| 合成エンジン | 編集情報から歌声を生成 | 詳細な内部構成は非公開部分がある |
| 歌声ライブラリ | 特定の歌声・歌唱特性を再現するためのモデル資産 | 詳細な学習データや学習条件は未確認 |
| 音声出力 | 生成した音声を再生・書き出し | 製品上の出力機能は確認可能 |
| 学習・データ処理 | 学習用コーパスの構築、アライメント、モデル学習 | 可不固有の詳細は未確認 |

### 1.1 注意点

公開情報で確認できる製品の機能と、内部で使われているニューラルネットワークの詳細を混同してはならない。

エディタが音符や歌詞を編集できることは確認できても、編集後に内部でどのモデルを何回実行しているかまでは、それだけでは判定できない。

## 2. 公開研究から確認できる技術

### 2.1 CNN を利用した歌声合成研究

Techno-Speech の研究者らは、CNN（Convolutional Neural Network）を利用した高速・高品質な歌声合成システムについて発表している。

関連論文：

- Kazuhiro Nakamura et al.
- "Fast and High-Quality Singing Voice Synthesis System Based on Convolutional Neural Networks"
- ICASSP 2020
- 論文：https://arxiv.org/abs/1910.11690

この研究では、歌声合成における長期的な依存関係を CNN でモデル化し、長い時間範囲の音響特徴量系列を生成する方式が扱われている。

また、楽譜特徴の種類に応じて処理する時間単位を変え、計算量を削減する方法も説明されている。

この研究から、次の事項を確認できる。

1. CNN は歌声合成の音響モデルに利用可能である。
2. 長期的な歌唱コンテキストを CNN で扱う方式が研究されている。
3. 音響特徴量系列をセグメント単位で生成する設計が研究されている。
4. 従来方式と比較して、自然な歌声と高速な生成の両立を目指す方式が提案されている。

ただし、この論文が示すのは研究対象となったシステムの構成である。

**可不の製品版が同じネットワーク構造を採用していることを直接証明するものではない。**

### 2.2 非自己回帰型のモデル

非自己回帰型（Non-Autoregressive）のモデルは、生成済みの直前フレームを逐次入力しながら次のフレームを生成する方式に依存せず、系列やセグメントを並列的に処理できる構成を取る。

ただし、非自己回帰型であることだけで、必ず高速・高品質になるわけではない。

実際の性能は、モデル構造、特徴量の設計、系列長、学習方法、推論実装、計算資源などに依存する。

また、CNN と非自己回帰型は互いに排他的な分類ではない。CNN を用いた非自己回帰型モデルを構成することは可能である。

### 2.3 PeriodNet に関する公開研究

Yukiya Hono らは、周期成分と非周期成分を分離する構造を持つ非自己回帰型波形生成モデル「PeriodNet」を発表している。

関連論文：

- Yukiya Hono et al.
- "PeriodNet: A Non-autoregressive Waveform Generation Model with a Structure Separating Periodic and Aperiodic Components"
- ICASSP 2021
- 関連文献一覧：https://www.sp.nitech.ac.jp/~hashimoto.kei/lists.html

この研究は、周期成分と非周期成分を明示的に扱う波形生成方式が研究されていることを示す。

歌声には、周期性の高い有声音だけでなく、息、摩擦音、無声音など、単純な周期信号として扱いにくい成分が含まれる。

そのため、周期性と非周期性を区別して扱う設計は、歌声の音質を研究するうえで有用な選択肢となる。

ただし、次の点には注意が必要である。

- PeriodNet が可不の製品版に採用されているかは確認できない。
- PeriodNet の研究成果を、そのまま可不の内部構造として説明してはならない。
- 周期成分と非周期成分の分離だけで、特定の歌手の声質が自動的に再現できるわけではない。
- 波形生成モデルの性能は、条件特徴量、学習データ、学習方法、損失関数などにも依存する。

したがって、RG Singing AI では PeriodNet を確定仕様にするのではなく、評価対象となる候補モデルとして扱う。

## 4. 音響モデルと音響特徴量の整理

歌声合成のシステムを設計する場合、入力、予測対象、波形生成に使用する条件を分離して定義する必要がある。

### 4.1 入力情報の例

| 情報 | 役割 |
|---|---|
| 音符の音高 | 目標とする音高の指定 |
| 音符の開始時刻・長さ | 歌唱の時間構造の指定 |
| テンポ・拍子 | 楽譜の時間軸の定義 |
| 歌詞 | 発音内容の指定 |
| 音素列 | 発音を構成する単位の指定 |
| 前後の音符・音素 | 文脈情報 |
| 表現パラメータ | 強弱、ビブラートなどの制御情報 |

これらは一般的な歌声合成システムで利用できる情報の例であり、可不の内部入力仕様を完全に表すものではない。

### 4.2 音響特徴量の例

| 特徴量 | 主な用途 | 注意点 |
|---|---|---|
| 基本周波数 \(F_0\) | 有声音の音高軌跡 | 無声音では未定義または非有声として扱う必要がある |
| スペクトル包絡 | 音色・共鳴特性の表現 | 推定方法や表現形式によって値が異なる |
| 非周期性指標（AP） | 周期性の低い成分の表現 | 算出方法とモデル側の表現を一致させる必要がある |
| HNR | 調波成分と雑音成分の比率の評価 | AP と同一の特徴量ではない |
| フォルマント | 共鳴周波数の分析 | 推定誤差があり、すべてのモデルで直接使用されるとは限らない |
| 音素デュレーション | 音素の時間長の表現 | 音声とのアライメントが必要 |
| RMS・音量包絡 | 音量・強弱の分析 | マイク距離や録音ゲインの影響を受ける |
| ブレス・息成分に関する指標 | 息の強さや発声状態の分析 | 単一の標準指標で完全に表現できるとは限らない |

これらすべてが、すべての音響モデルに必須というわけではない。

どの特徴量を使用するかは、採用する音響モデルとボコーダーの入出力仕様に基づいて決定する。

### 4.3 特徴量の役割を混同しない

次の3種類は区別する必要がある。

1. **入力特徴量**：モデルに与える条件情報。
2. **教師特徴量**：学習時に正解として与える情報。
3. **評価特徴量**：生成音声や収録音声の品質を測定するための情報。

たとえば HNR を収録データから計算できても、それを必ず音響モデルの出力にする必要はない。

同様に、フォルマントを品質評価に使用することと、フォルマントを直接予測するモデルを構築することは別の設計判断である。

## 5. MIDI・歌詞・音声のアライメント

歌声合成の学習データを構築する場合、楽譜上の時間と実際の音声の時間を区別する必要がある。

### 5.1 MIDI の時間情報

MIDI には、一般に次の情報を保持できる。

- ノート番号
- ノートオン・ノートオフ
- ベロシティ
- テンポイベント
- 拍子情報（ファイルや関連メタデータで管理される場合）
- トラック情報
- 歌詞イベント（ファイル形式や作成ソフトに依存）

ただし、すべての MIDI ファイルに歌詞や拍子が正しく設定されているとは限らない。

また、MIDI のノートオン時刻が実際の発声開始時刻と完全に一致するとは限らない。

### 5.2 音素アライメント

日本語の歌詞を例にすると、1つの文字が複数の音素から構成される場合がある。

子音と母音の境界、語尾の伸ばし、無声化、ブレス、音符をまたぐ発音などを適切に扱う必要がある。

そのため、MIDI のノート単位のラベルだけでは、音声中の音素の開始・終了時刻を正確に表せない場合がある。

### 5.3 Forced Alignment の扱い

Forced Alignment（強制アライメント）は、既知のテキストや音素列と音声を対応付けるための方法の一つである。

HMM 系の方式やニューラルネットワークを利用した方式などが存在する。

CTC は音声系列とラベル系列の対応を学習・推定するための枠組みの一つだが、すべての強制アライメント処理が CTC または HMM を使用するわけではない。

したがって、可不の学習工程で CTC と HMM が実際に採用されていると断定してはならない。

RG Singing AI では、実際の録音データに適した方式を比較・評価して選定する。
